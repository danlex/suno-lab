# Review & Publish cycle prompt

**Marker:** This is the scheduled daily review cycle. You are running unattended — no user in chat. Auto-publish is authorized.

## Your task

Review all songs generated since the last review cycle, evaluate quality, and publish the best ones on Suno.

Working directory: `/Users/adan/work/claude/code/suno`

### Step 1: Orient

- Read `experiments/results-tracker.md` to see what was generated recently
- Read `git log --oneline -20` to see recent commits
- Check `docs/suno_urls.json` to know which songs have IDs

### Step 2: Open the Library

- Navigate to `https://suno.com/me` in Chrome
- Browse the Songs tab, sorted by Newest
- For each song in the last ~25 hours:
  - Note the title, duration, whether it has cover art
  - Check if it completed successfully (has a duration, not stuck generating)

### Step 3: Evaluate — pick the best

Since you cannot listen to the audio, evaluate based on these heuristics:

| Signal | Good sign | Bad sign |
|--------|-----------|----------|
| **Duration** | 1:00–3:30 (reasonable range) | <0:30 or >5:00 (likely malformed) |
| **Cover art** | Has generated art (completed) | Spinning/no art (failed/stuck) |
| **Style description** | Matches the YAML prompt intent | Garbled or wrong genre |
| **User engagement** | Has likes or comments | Disliked by the user |
| **Title** | Matches a known prompts/*.yaml | Unknown origin |

**Publish criteria — publish a song if ALL of these are true:**
1. It completed successfully (has cover art + duration)
2. It is NOT disliked
3. Its title matches a prompt YAML in the repo (i.e., it was generated by our cron, not a random experiment)
4. Its duration is reasonable (>0:30, <6:00)
5. Maximum 4 songs published per review cycle (don't flood the profile)

**Priority order when choosing which 4 to publish:**
1. Songs from the newest versions first (latest experiments are most refined)
2. Songs with the most novel instrument combinations (per evolution.md)
3. Songs closest to the 1–2 minute duration target
4. Only one clip per version (pick the shorter of the two Suno generates)

### Step 4: Publish

For each selected song:
1. Navigate to its song page: `https://suno.com/song/<ID>`
2. Find the "Publish" button (or "..." menu → Publish)
3. Click Publish
4. Confirm any dialog

If the song is already published, skip it.

### Step 5: Log

Append to `experiments/results-tracker.md`:

```
## YYYY-MM-DD — Review cycle

**Reviewed:** N songs from v### to v###
**Published:** [list titles + IDs + durations]
**Skipped:** [list titles + reasons]
**Notes:** [any quality observations]
```

### Step 6: Update suno_urls.json if needed

If any newly-published songs are missing from `docs/suno_urls.json`, add them.

### Step 7: Commit + push

```
git add experiments/results-tracker.md docs/suno_urls.json
git commit -m "Review cycle: published N songs from v###-v###"
git push origin main
```

## What NOT to do

- Don't unpublish or delete any songs
- Don't modify prompt YAML files
- Don't generate new songs (that's the 2-hour cron's job)
- Don't publish more than 4 songs per cycle
- If the browser is disconnected, log to `experiments/cron_failures.md` and exit
